# Hash Race locked visual target

**Reference asset:** `Godot/art/reference/hashrace_visual_target_v121.png`

This image is a **design specification, not runtime proof**. Hash Race must recreate its composition through live Godot scenes, draw code, sprites, simulation data, and UI. The reference must never be substituted for a gameplay screenshot or drawn as a fake background.

## Required visual language

- Compact top HUD with Hash Race identity plus BTC Treasury, Cash, Power, Hashrate, and Efficiency.
- Neon green / black / dark-steel interface with restrained cyan, orange, and yellow status colors.
- Clean mining campus with large intentional structures instead of repeated small placeholder props.
- Mining-rig building, transformer, power module, storage yard, signage, fencing, lighting, and service details that read immediately.
- Readable road shoulders, lane markings, grass transitions, shoreline / terrain edges, and strong fixed-direction shadows.
- Sparse purposeful props and large negative space around important buildings.
- Green-accented directional player character with clear scale and placement.
- HUD panels must not cover the playable center of the map.

## Proof rule

Reference image = **target**.

`visual-proof/hashrace-screenshot.png` generated by the Godot 4.7.2 workflow = **proof**.

No release note, README entry, or chat response may call a visual change complete until the real Godot runtime capture passes the screenshot validation step. Generated concept art is never proof.

## v0.123 implementation

`world_v123.gd` replaces the live player-site gray-pad composition with a runtime-drawn mining-rig building, transformer, power module, storage yard, signs, lights, road striping, and compact load meter. `visual_target_hud.gd` replaces the duplicate always-visible Mining Ops panel with the target-style top HUD while retaining the existing Mining Ops node for its data contract and drawer behavior.
